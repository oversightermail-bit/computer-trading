## 一、实测诊断（2026-11-04，本机直连，无 Cookie）

| 天猫搜索 `list.tmall.com` | **302 重定向**到 `s.taobao.com/search?tab=mall`（同样的 SPA 壳） | `tmall.py` 的 `.product-iWrap` 选择器**已死**，永远 0 条 |

另：`爬虫/logs/crawl_stats.jsonl` 中唯一一轮记录是 `mode=mock`，说明本项目至今**没有一轮真实数据入库**。

### 根因（代码层面）

1. **auto 模式恒等于 mock**：`engine.collect_platform()` 里 `empty or banned` 就切换 mock。
   真实路径全部 0 解析 → 必然降级，且降级只打一行 warning，用户无感知。
2. **直抓路径没有限速、没有重试**：`download_delay` / `retry_times` 只在 Scrapy 分支生效；
   `jd/taobao/tmall.collect()` 的循环里没有任何 `sleep`，60 个请求连发，即使有 Cookie 也会秒封。
3. **代理池是死配置**：`config.ANTI_CRAWL["proxies"]` 只被 Scrapy 中间件使用；
   `fetcher.fetch()` 完全不读它（本机连 Scrapy 都没装，等于永远直连）。
4. **没有 Cookie 注入**：`fetcher.fetch()` 只带 UA/Accept 三个头。京东 pt_key/pt_pin、
   淘宝 `_m_h5_tk`/cookie2/unb 无从带入，而这恰是两大平台的准入条件。
5. **封禁特征词过时**：`ban_markers` 里没有"京东验证 / cfe.m.jd.com / risk_handler /
   当前人数过多"，且三个 spider 的 `detect_ban()` 各自硬编码，没用 config 里的统一清单。
6. **解析器失效无感知**：页面 200 但选择器全部落空（天猫现状）时，不留任何现场证据，
   只能靠猜。没有 debug 快照机制。
7. **本机缺依赖**：`requests/lxml/pandas/pymysql/scrapy` 均未安装，当前只能走 urllib 兜底 +
   SQL 文件输出。先 `pip install -r requirements.txt`。

## 二、P0：让"真抓"具备起码条件（改完立即可验证，任何方案的前提）

### 1. `fetcher.py` — 支持 Cookie/Referer/代理/重试

`fetch()` 增加 `referer / cookies / retries` 参数，启用代理池，失败指数退避重试：

```python
def _pick_proxy():
    proxies = config.ANTI_CRAWL.get("proxies") or []
    if not proxies:
        return None
    p = random.choice(proxies)
    return {"http": p, "https": p}

def fetch(url, timeout=None, referer=None, cookies=None, retries=None):
    timeout = timeout or config.ANTI_CRAWL["timeout"]
    retries = config.ANTI_CRAWL["retry_times"] if retries is None else retries
    headers = {
        "User-Agent": random_ua(),
        "Accept": "text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8",
        "Accept-Language": "zh-CN,zh;q=0.9",
        "Accept-Encoding": "gzip, deflate",
        "Connection": "keep-alive",
    }
    if referer:
        headers["Referer"] = referer
    if cookies:
        headers["Cookie"] = cookies
    last_err = ""
    for attempt in range(retries + 1):
        try:
            r = requests.get(url, headers=headers, timeout=timeout,
                             allow_redirects=True, proxies=_pick_proxy())
            if r.status_code >= 400 and attempt < retries:
                time.sleep(config.ANTI_CRAWL["download_delay"] * (attempt + 1))
                continue
            return r.text, r.url, ""
        except Exception as e:
            last_err = str(e)
            if attempt < retries:
                time.sleep(config.ANTI_CRAWL["download_delay"] * (attempt + 1))
    return "", url, last_err
```

### 3. 三个 spider 的 `collect()` — 加限速

`jd.py` / `taobao.py` / `tmall.py` 的 `collect()` 循环里，每次 `fetch()` 前：

```python
import time

for page in range(1, limit_pages + 1):
    ...
```

同时把各平台 `detect_ban()` 改为统一读 `config.ANTI_CRAWL["ban_markers"]`，
删掉三个文件里互相不一致的硬编码词表。

## 三、P1：京东 —— 让价格真正入库

实测结论：京东**详情页可直连**，搜索页与价格接口都拦无 Cookie 请求。改法：

1. **首选：带登录 Cookie 抓搜索列表页**
   - 浏览器登录 jd.com → F12 → 复制 Cookie（含 `pt_key`、`pt_pin`）→ 填进
     `config.ANTI_CRAWL["cookies"]["京东"]`。
   - 带 Cookie + 限速 ≥3s + 代理池后，`search.jd.com/Search` 会返回服务端渲染的
     `li.gl-item` 列表，现有 XPath 大概率仍可用。
   - 请求头上再加 `Referer: https://www.jd.com/`。
2. **价格补价接口修正**：`jd.py` 的 `_fetch_sku_price()` 必须带
   `Referer: https://item.jd.com/<sku>.html` 与 Cookie，并走 `fetch()` 的重试逻辑。
   本机实测 p.3.cn 直连超时，配置代理后再验证；不通则该平台当天价格缺失，
   由监控告警（不要用 mock 悄悄掩盖）。
3. **备用：详情页直抓**（不依赖搜索页）：`CATALOG` 为每个型号预填京东商品链接
   （见 P3），抓 `item.jd.com/<sku>.html` 后从 `pageConfig` 提取 SKU 信息，
   价格仍走 p.3.cn（带 Referer）。详情页风控明显比搜索页松。
4. **放弃**：`item-soa.jd.com/getWareBusiness` 已下线，不要写进代码。

## 四、P2：淘宝 / 天猫 —— 必须换抓取方式（旧解析已死）

实测结论：两家搜索页都是 React SPA 壳，服务端 HTML 里**没有任何商品数据**。
`taobao.py` 的 g_page_config 解析、`tmall.py` 的 CSS 选择器必须重写。两条路线二选一：

### 路线 A：mtop h5 接口直连（轻量，需登录 Cookie）

淘宝 h5 搜索真实接口：`h5api.m.taobao.com/h5/mtop.taobao.wsearch.h5search/1.0/`。
签名算法公开：`sign = md5(token & t & appKey & data)`，token 取自 Cookie `_m_h5_tk`
下划线前半段：

```python
import hashlib, json, time as _t
from urllib.parse import quote

APP_KEY = "12574478"  # 淘宝 h5 公开 appKey

def mtop_search(keyword, page, cookie):
    token = cookie.split("_m_h5_tk=")[1].split(";")[0].split("_")[0]
    t = str(int(_t.time() * 1000))
    data = json.dumps({"q": keyword, "page": page}, separators=(",", ":"))
    sign = hashlib.md5(("%s&%s&%s&%s" % (token, t, APP_KEY, data)).encode()).hexdigest()
    url = ("https://h5api.m.taobao.com/h5/mtop.taobao.wsearch.h5search/1.0/"
           "?jsv=2.6.1&appKey=%s&t=%s&sign=%s&api=mtop.taobao.wsearch.h5search"
           "&v=1.0&type=json&dataType=json&data=%s" % (APP_KEY, t, sign, quote(data)))
    # GET，带 Cookie、Referer: https://s.m.taobao.com/、UA 用手机版
    return url
```

响应 `data.listItem` 里的字段：`title / price / shopName / item_id / pics`。
天猫即淘宝 `tab=mall` 结果（或 `sst` 参数换频道），**一套解析器两家共用**。
缺点：接口参数不定期变更、触发滑块后需人工换 Cookie。

### 路线 B：Playwright 渲染（最稳，重但一劳永逸）

```python
# requirements.txt 加：playwright>=1.40
# 首次：playwright install chromium
from playwright.sync_api import sync_playwright

def collect_browser(keyword, storage_state=None):
    with sync_playwright() as p:
        browser = p.chromium.launch(headless=True)
        ctx = browser.new_context(storage_state=storage_state, locale="zh-CN")
        page = ctx.new_page()
        page.goto("https://s.taobao.com/search?q=%s" % keyword,
                  wait_until="domcontentloaded", timeout=45000)
        page.wait_for_selector(".Card--doubleCard", timeout=30000)  # 商品卡片
        cards = page.query_selector_all(".Card--doubleCard")
        for c in cards:
            title = (c.query_selector(".Card--titleWrapper") or c).inner_text()
            price = (c.query_selector(".Price--priceInt") or c).inner_text()
            shop  = (c.query_selector(".ShopInfo--shopName") or c).inner_text()
            yield title, price, shop
        browser.close()
```

关键点：人工登录淘宝一次后 `ctx.storage_state(path=...)` 保存，
此后复用；被封时人工再登录一次。天猫直接访问 `list.tmall.com`（浏览器里自动落在
`tab=mall` 结果页，卡片结构相同）。这条路线同样能救京东（JS 渲染的价格）。

**建议组合**：日常用路线 A（轻量、可定时），把路线 B 作为 A 被封时的真实兜底，
让 mock 变成"最后一道防线"而不是唯一数据源。

## 五、P3：架构级建议（降低对搜索页的依赖）

1. **目录预置固定商品链接**：`config.CATALOG` 每项加 `"jd_url" / "tb_url" / "tm_url"`
   字段，45 个型号 × 3 平台人工录一次。之后每轮**只抓详情页价格**（详情页风控最松），
   搜索页仅作新增型号的发现渠道。这是三个平台里唯一"不依赖登录 Cookie 也有机会通"的
   稳定形态（京东详情页实测 200）。
2. **增加次级真实数据源**：见下节"六、替代数据源方案"——实测慢慢买、
   什么值得买、惠惠网均已不可用；可行的真实替补是**京东联盟 API**与**ZOL 参考报价**。
   某平台被封时切换为这些源（source 标注来源），mock 只兜底全灭。
3. **监控区分两类失败**（`monitor.py`）：
   - 封禁（风控页/验证码）→ 提示换 Cookie/换代理；
   - 解析器失效（页面 200、无封禁特征、解析 0 条）→ 提示"平台改版，请更新解析器"。
   目前两者混为一谈，都会静默降级 mock。
4. **成功率口径改为"入库率"**：`parsed/requested` 会因列表页正常波动误报；
   建议告警看 `prices_written / expected(45型号×平台)`，并单独报告 mock 占比。
   建议在 `MONITOR` 里加 `"max_mock_ratio": 0.3`，mock 占比超阈值也告警——
   否则"天天告警但折线全是模拟数据"没有任何意义。

## 六、替代数据源方案（实测 2026-11-04）

如果不想和三大平台的反爬正面硬刚，换数据源是最快的"真数据"路线。实测结果：

| 候选源 | 实测结果 | 结论 |
|---|---|---|
| **京东联盟开放平台 API** | `api.jd.com/routerjson` 连通，返回"appkey 为空"的正常报错 | ✅ **最推荐**：官方渠道，注册 appKey 即可拿京东真实价格，无封禁 |
| **中关村在线 ZOL** | 分类页 `detail.zol.com.cn/cpu/` 200（240KB）；型号页 `indexXXXX.shtml` 200（228KB），含 `<b class="price-type">1830</b>` 参考报价，GBK 编码 | ✅ **可用**：无需登录、无验证、结构稳定，可作真实基准价源 |
| 太平洋 PConline | 分类页 200；型号页 302 无 Location（需跟重定向/cookie） | ⚠️ 次选，可用但比 ZOL 麻烦 |
| 淘宝联盟（淘宝客 API） | 需网站备案 + 资质审核 | ❌ 学生/个人项目门槛高 |
| 慢慢买 | `search.aspx` 已 404（改版） | ❌ 不可用 |
| 什么值得买 | 202 + JS 挑战（瑞数 probe.js） | ❌ 不可用 |
| 惠惠网 | 已跳转有道（站点已死） | ❌ 不可用 |

### 方案对比

| 方案 | 数据真伪 | 能否覆盖三平台口径 | 实施成本 |
|---|---|---|---|
| A. 京东列 = 京东联盟 API；天猫/淘宝列 = Playwright + 登录 Cookie | 全真实 | 保口径 ✅ | 中 |
| B. 京东列 = 京东联盟 API；天猫/淘宝列 = ZOL 参考价（页面标注来源） | 全真实 | 口径近似 ⚠️ | **低（最推荐落地）** |
| C. 口径改为"京东联盟 / ZOL / PConline"三源 | 全真实 | 改前后端展示 | 高 |
| D. 全部 Playwright 渲染三平台 | 全真实 | 保口径 | 高（重、慢、需维护） |

### 方案 B 落地代码（京东联盟 API）

1. 注册 [京东联盟](https://union.jd.com)（个人身份证即可）→ 创建"网站"应用 →
   拿到 `appKey` + `secretKey`；
2. 填进 `config.py`：

```python
JD_UNION = {"app_key": "换成你的", "secret_key": "换成你的"}
```

3. 新文件 `hwspider/spiders/jd_union.py`（官方 `jd.union.open.goods.query` 接口）：

```python
# -*- coding: utf-8 -*-
"""京东联盟开放平台：官方关键词搜索接口，返回真实商品与价格。"""
import hashlib
import json
from datetime import datetime
from urllib.parse import urlencode
from urllib.request import Request, urlopen

from .. import config


def _sign(params: dict, secret: str) -> str:
    s = secret + "".join(k + params[k] for k in sorted(params)) + secret
    return hashlib.md5(s.encode("utf-8")).hexdigest().upper()


def search(keyword: str, page_index: int = 1, page_size: int = 10) -> list:
    """返回 [{title, price, shop, sku_id, url}, ...]，失败抛异常"""
    c = config.JD_UNION
    params = {
        "method": "jd.union.open.goods.query",
        "app_key": c["app_key"],
        "timestamp": datetime.now().strftime("%Y-%m-%d %H:%M:%S"),
        "format": "json",
        "v": "1.0",
        "sign_method": "md5",
        "360buy_param_json": json.dumps(
            {"goodsReqDTO": {"keyword": keyword, "pageIndex": page_index,
                             "pageSize": page_size}},
            ensure_ascii=False, separators=(",", ":")),
    }
    params["sign"] = _sign(params, c["secret_key"])
    body = urlencode(params).encode()
    req = Request("https://api.jd.com/routerjson", data=body,
                  headers={"User-Agent": config.ANTI_CRAWL["user_agents"][0]})
    with urlopen(req, timeout=10) as resp:
        data = json.loads(resp.read().decode("utf-8"))
    if data.get("error_response"):
        raise RuntimeError(data["error_response"].get("zh_desc", "京东联盟接口错误"))
    out = []
    node = (data.get("jd_union_open_goods_query_responce")
            or data.get("jd_union_open_goods_query_response")) or {}
    result = node.get("queryResult") or node.get("result") or []
    for g in result:
        pi = g.get("priceInfo") or {}
        out.append({
            "title": g.get("skuName", ""),
            "price": pi.get("lowestPrice") or pi.get("price"),
            "shop": (g.get("shopInfo") or {}).get("shopName", ""),
            "sku_id": g.get("skuId"),
            "url": "https://item.jd.com/%s.html" % g.get("skuId"),
        })
    return out
```

> 不同联盟版本返回节点名可能是 `jd_union_open_goods_query_responce`（官网原样
> 拼写）或 `..._response`，上面两个都兼容；首次调用打印一次完整 JSON 确认即可。
